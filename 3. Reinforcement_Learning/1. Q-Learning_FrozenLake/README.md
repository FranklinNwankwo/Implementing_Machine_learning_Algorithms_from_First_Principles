# Q-Learning from First Principles — FrozenLake Reinforcement Learning

An end-to-end reinforcement learning project implementing tabular Q-Learning using only NumPy, applied to policy learning in Gymnasium's [FrozenLake-v1](https://gymnasium.farama.org/environments/toy_text/frozen_lake/) environment, under both deterministic and stochastic transition dynamics.

Built to understand Q-Learning's full mathematical machinery; the Bellman optimality equation, temporal-difference targets, off-policy bootstrapping, terminal-state handling, with no reliance on a prebuilt RL agent or library, and validated against an independently-implemented dynamic-programming oracle rather than any `sklearn` accuracy metric (which has no notion of sequential decision-making and cannot validate this kind of model).

---

## Project Overview

Unlike supervised learning, there is no labelled `(input, correct_output)` dataset here: the agent learns an action-value function $Q(s,a)$ purely from `(state, action, reward, next_state)` experience generated by interacting with the environment, using only a sparse reward signal (+1 on reaching the goal, 0 everywhere else, including falling into a hole). This project implements that idea from first principles:

1. **Mathematical Derivation** — the FrozenLake MDP formulation, the Bellman optimality equation, and its reduction to the sample-based Q-Learning temporal-difference update, worked out before any code is written
2. **From-Scratch Implementation** — a unified `train_td_agent` function (NumPy only) implementing Q-Learning, SARSA, and Expected SARSA via a shared episode loop that differs only in TD-target computation; a separate two-table `train_double_q` function for Double Q-Learning; a separate first-visit `train_mc_control` function for Monte Carlo Control
3. **Correct Terminal Handling** — `terminated` and `truncated` are read as distinct flags from Gymnasium's `step()`, so bootstrapping is suppressed only on genuine MDP termination (goal/hole), never on a time-limit truncation
4. **Fair Epsilon-Greedy Exploration** — ties among maximal Q-values are broken uniformly at random rather than defaulting to the first action, avoiding a systematic bias toward `Left` early in training when most Q-values are still zero

This project walks through the full RL validation pipeline:

- **Environment Audit** — state/action space inspection, map and reward-structure verification, and a direct comparison of the deterministic vs. stochastic transition tables (`env.unwrapped.P`)
- **Random-Policy Baseline** — the reference floor (1.35% deterministic, 1.85% stochastic success) that any learned policy is measured against
- **Training Diagnostics** — rolling success rate, Q-table change (mean $|\Delta Q|$), policy-stability tracking, and TD-error distribution, used to establish *empirical* stabilization
- **Independent Validation** — a from-scratch value-iteration oracle (dynamic programming over the environment's true transition table), used only for validation, never as the training algorithm, plus exact Bellman-residual diagnostics
- **Hyperparameter Sensitivity Analysis** — a one-at-a-time sweep over learning rate $\alpha$, discount factor $\gamma$, and epsilon-decay schedule
- **Multi-Seed Benchmarking** — 10 independent seeds (deterministic) / 6 independent seeds (stochastic), reported as mean ± std, not a single training run
- **Algorithm Comparison** — Q-Learning benchmarked against SARSA, Expected SARSA, Double Q-Learning, and Monte Carlo Control, all trained under an identical environment, episode budget, and seed set
- **Theoretical vs. Empirical Convergence** — an explicit discussion of why a constant learning rate does not satisfy the Robbins-Monro conditions classical Q-Learning convergence proofs require, plus an optional diminishing-$\alpha$ variant that does

Key issues encountered and resolved during the project:

- **`terminated` vs. `truncated` conflation would have silently corrupted the value function** — FrozenLake-v1's default `TimeLimit` wrapper sets `truncated=True` after 100 steps on a *non-terminal* state; treating that the same as `terminated` would have told the agent "this state has zero future value" purely because of a wall-clock cutoff. The training loop reads both flags explicitly and only suppresses bootstrapping on genuine termination.
- **A single sampled Bellman residual is not the same diagnostic in a stochastic environment** — for the deterministic configuration the exact Bellman residual can be computed directly from the known transition table; for the stochastic configuration a single observed transition's residual is a noisy sample of a random variable, not the expectation, so this distinction is stated explicitly rather than reporting one number as if it meant the same thing in both settings.
- **Constant learning rate does not satisfy classical convergence theory** — $\alpha=0.20$ (deterministic run) and $\alpha=0.10$ (stochastic run) violate the Robbins–Monro condition $\sum \alpha_t^2 < \infty$. Rather than describing the flat training curves as "convergence," the notebook explicitly distinguishes *empirical stabilization* (small, decreasing $|\Delta Q|$ and policy-change rate within a finite budget) from the theorem-backed asymptotic guarantee, and implements a diminishing-$\alpha_t = \alpha_0/\text{visits}(s,a)$ variant that does satisfy the theoretical conditions as a separate, optional comparison.
- **Random policy-agreement ties across untested states would have overstated correctness if measured naively** — several non-terminal states have multiple equally-optimal actions under the true dynamics (symmetric detours, states off the optimal path); policy agreement with the value-iteration oracle is reported for all states *and* restricted to non-terminal states, alongside state-value correlation and mean absolute value error, rather than relying on raw action-match percentage alone.
- **A single training run can look successful by chance** — every headline result (deterministic success rate, stochastic success rate, the algorithm comparison) is reported across multiple independent seeds as mean ± std, not from one lucky run; this is what surfaced SARSA's seed-sensitivity (see Results).

Selected via a one-at-a-time hyperparameter sensitivity sweep on the deterministic environment rather than a single arbitrary choice; every tested variant reached 100% evaluation success, with sensitivity showing up instead in *training-phase* stability (e.g. a slow epsilon-decay schedule reaching only 58% success in the final 500 training episodes despite eventually recovering to 100% at evaluation).

## Limitations

- **FrozenLake is a toy environment**: a 16-state, 4-action grid is small enough to validate exhaustively, that is precisely its value here, but a 100% success rate on it is a correctness demonstration, not evidence of readiness for real robotics, navigation, or control.
- **Tabular representation does not scale**: the $O(|S|\cdot|A|)$ Q-table (64 floats here) becomes intractable the moment the state space is continuous or high-dimensional (pixels, joint angles), which is the direct motivation for function-approximation methods like DQN, implemented conceptually in the notebook's discussion, not in code.
- **A constant learning rate does not satisfy classical convergence theory**: the primary runs use $\alpha=0.20$/$0.10$, which violates the Robbins–Monro conditions required for a formal convergence guarantee. The flat training curves and small $|\Delta Q|$ observed are empirical stabilization within a finite episode budget, not proof of convergence to $Q^*$ — the notebook is explicit about this distinction rather than conflating the two.
- **Stochastic-environment performance has a hard ceiling that better hyperparameters cannot remove**: even a correctly-learned optimal policy under `is_slippery=True` will fall into a hole on some fraction of episodes purely from an unlucky slip; 73–75% success (vs. 100% deterministic) reflects genuine environment randomness, not an undertrained agent.
- **On-policy algorithms can be seed-sensitive in ways off-policy algorithms are not**: SARSA reached 100% success on 5 of 6 benchmark seeds but got stuck on one, pulling its mean to 83.33% with a std of 40.82, a real finding about on-policy TD sensitivity to early trajectories in a sparse-reward setting, not a bug (see Results).
- **Bellman-residual diagnostics require access to the true environment dynamics**: the exact residual computed here uses `env.unwrapped.P` directly, which is available only because FrozenLake is a fully-known, small environment; a real deployed agent would not have this and would need to rely on sampled (noisier) residuals instead.

|---|---|---|---|
| Deterministic (`is_slippery=False`) | 1.35% | **100.00%** | 6.00 steps |
| Stochastic (`is_slippery=True`) | 1.85% | **73.00%** | 44.72 steps |

**Independent validation against a from-scratch value-iteration oracle (deterministic environment, $\gamma=0.99$, converged in 7 sweeps):**

| Metric | Value |
|---|---|
| Policy agreement (all states) | 100.0% |
| Policy agreement (non-terminal states) | 100.0% |
| State-value correlation with oracle | 1.0000 |
| Mean absolute value error vs. oracle | 0.0000 |
| Mean absolute Bellman residual | 0.00082 |
| Max absolute Bellman residual | 0.04301 |

The learned Q-table matches the independently-derived optimal policy and value function exactly, this is the correctness evidence `sklearn` could not have provided.

**Multi-seed benchmarking (mean ± std, deterministic: 10 seeds / stochastic: 6 seeds):**

| Environment | Success rate | Mean episode length |
|---|---|---|
| Deterministic | 100.00% ± 0.00% | 6.00 ± 0.00 |
| Stochastic | 74.9% ± 1.61% | 44.55 ± — |

Zero variance across 10 independent seeds on the deterministic environment confirms the result is reproducible, not one lucky run; the stochastic environment's non-zero std is the direct, expected consequence of genuine transition randomness rather than training instability.

**Algorithm comparison** (same environment, 6,000-episode budget, identical 6-seed set, deterministic FrozenLake):

| Algorithm | Success rate (mean ± std) | Mean episode length | Episodes to 70% rolling success | Policy agreement with oracle |
|---|---|---|---|---|
| Q-Learning (off-policy) | 100.00% ± 0.00% | 6.00 | 2,210 | 93.9% |
| SARSA (on-policy) | 83.33% ± 40.82% | 21.67 | 2,342 | 78.8% |
| Expected SARSA (on-policy) | 100.00% ± 0.00% | 6.00 | 2,167 | 95.5% |
| Double Q-Learning (off-policy) | 100.00% ± 0.00% | 6.00 | 2,326 | 83.3% |
| Monte Carlo Control | 100.00% ± 0.00% | 6.00 | 2,526 | 72.7% |

SARSA reached 100% success on 5 of its 6 benchmark seeds but got stuck at 0% on one, a genuine on-policy sensitivity to early trajectory outcomes in a sparse-reward environment, and the reason its std (40.82) dwarfs every other algorithm's (0.00). All other algorithms were perfectly stable across every seed at this budget.

**Hyperparameter sensitivity** (deterministic environment, 10,000 episodes): every tested variant of $\alpha \in \{0.05, 0.20, 0.50\}$, $\gamma \in \{0.90, 0.99, 0.999\}$, and epsilon-decay reached 100% *evaluation* success — the sensitivity surfaces instead in training-phase stability, where a slow epsilon-decay (0.9999) reached only 58.0% success in the final 500 training episodes (still exploring too much this late) versus 99.0% for the baseline decay (0.9995), and a constant $\epsilon=0.1$ (never fully exploiting) reached 89.8%.

**Robbins–Monro diminishing learning rate** (optional theoretical-convergence check, $\alpha_t = 1/\text{visits}(s,a)$): reached the same 100.00% evaluation success as the constant-$\alpha$ baseline, with 81.8% policy agreement between the two variants on non-terminal states, both find a correct optimal policy, differing only at states with genuine action ties.

## What I learned:

1. **`terminated` and `truncated` Are Not Interchangeable, and Conflating Them Is a Silent Correctness Bug.**

It would have been easy to write `done = terminated or truncated` and then bootstrap based on `done` alone. The two flags mean genuinely different things — one says "the MDP itself is over," the other says "an external clock ran out" — and only the first should ever suppress the TD target's bootstrap term. Handling them explicitly, and stating why in the notebook, turned a subtle spec requirement into a concrete implementation detail I now check for by default in any episodic RL loop.

2. **Off-Policy vs. On-Policy Is Not an Abstract Distinction — It Shows Up Directly in Seed Variance.**

Watching SARSA get stuck on exactly one of six seeds while Q-Learning, Expected SARSA, Double Q-Learning, and Monte Carlo Control were perfectly stable across all six made the theoretical on-policy/off-policy distinction concrete: SARSA's value estimates are entangled with its own exploratory behavior, so an unlucky early trajectory can anchor it somewhere Q-Learning's greedy-target bootstrapping never would. This is exactly the kind of result a single training run would have hidden, and exactly why the multi-seed benchmark exists.

3. **A Flat Training Curve Is Not a Convergence Proof, and the Gap Between the Two Is Precise, Not Vague.**

It's tempting to see a stabilized reward curve and call it "converged." The Robbins–Monro conditions ($\sum\alpha_t=\infty$, $\sum\alpha_t^2<\infty$) give a specific, checkable reason a constant learning rate doesn't qualify, and implementing the diminishing-$\alpha$ variant alongside the constant-$\alpha$ baseline turned that from a caveat into something directly testable: both reached the same policy, which is reassuring, but only one of them is backed by the classical theorem.

4. **An Independently-Implemented Oracle Is a Much Stronger Validation Than a Metric Score.**

Value iteration and Q-Learning share almost nothing at the code level; one sweeps the full known transition table to convergence, the other learns from single sampled transitions with no knowledge of $P$ in advance. Getting 100% policy agreement and zero value error between two algorithms that don't share a bug surface is categorically stronger evidence of correctness than any single accuracy-style number could have been, which is exactly the validation strategy `sklearn` couldn't have offered here.

5. **Sparse Rewards Make Exploration Scheduling the Real Lever, Not the Learning Rate.**

Every tested $\alpha$ and $\gamma$ variant reached the same 100% evaluation success, the actual sensitivity showed up entirely in the epsilon-decay schedule, where too-slow decay left the agent still exploring 42% of the time in its final 500 training episodes. In a sparse-reward environment where the only positive signal sits several steps from any given state, getting enough greedy exploitation in before the episode budget runs out mattered far more than fine-tuning the update-rule coefficients.

6. **Fair Algorithm Comparison Requires Matching Everything Except the Algorithm.**

Benchmarking five different update rules only produces an interpretable result if the environment, episode budget, exploration schedule, and random-seed set are held identical across all five, otherwise a difference in outcome could just as easily be a difference in experimental setup. Building one shared `train_td_agent` dispatcher for the three single-table algorithms (rather than three separate near-duplicate loops) was what made it practical to guarantee that.
