# Gaussian Mixture Model from Scratch — Olivetti Faces Clustering

An end-to-end machine learning project implementing a Gaussian Mixture Model using only NumPy/SciPy, applied to unsupervised probabilistic clustering on the [Olivetti Faces dataset](https://scikit-learn.org/stable/datasets/real_world.html#the-olivetti-faces-dataset) (400 grayscale images, 40 subjects).

Built to understand EM's full mathematical machinery, log-space Gaussian densities, Cholesky-based numerical stability, responsibility computation, closed-form M-step updates, with no reliance on `sklearn.mixture` until the custom implementation was fully derived, validated on synthetic data, and fit on real face data.

---

## Project Overview

Unlike K-Means' hard cluster assignment, a GMM models the data as generated by a finite number of latent Gaussian subpopulations and gives every observation a **probability of belonging to every component**. This project implements that idea from first principles:

1. **Mathematical Derivation** — the mixture density, the E-step responsibility formula, and the M-step's closed-form responsibility-weighted parameter updates, worked out in full before any code is written
2. **From-Scratch Implementation** — a `GaussianMixtureScratch` class (NumPy/SciPy only) supporting four covariance structures (`full`, `diag`, `spherical`, `tied`), Cholesky-based log-density evaluation with a regularization back-off, log-sum-exp responsibility normalization, multi-restart fitting (`n_init`), and `aic()`/`bic()` model-selection helpers
3. **Synthetic Validation** — recovering known ground-truth parameters (means, weights) from a 3-component synthetic mixture, plus a near-singular-covariance edge case, before ever touching the real image data
4. **A Strict Label-Leakage Discipline** — subject identity is never used to fit the GMM, initialize it, or choose K; it is used only *after* training, for external validation and interpretation, with every place this matters called out explicitly in the notebook

This project walks through the full unsupervised learning pipeline:

- **Exploratory Data Analysis (EDA)** — structural audit (shape, pixel range, duplicates, per-subject counts), representative faces, within-subject pose/lighting variation, pixel-intensity distribution, and the dataset "mean face"
- **Preprocessing** — an 80/20 raw-index train/evaluation split (not stratified by identity, to avoid smuggling in label information), and PCA fit only on the training partition
- **Dimensionality Reduction** — PCA retaining 60 components (~89.5% cumulative explained variance), chosen to keep a 60×60 full covariance matrix (1,830 free parameters) estimable from a few hundred training images
- **Model Implementation** — `GaussianMixtureScratch`: log-space Gaussian densities via Cholesky decomposition and triangular solves, a covariance regularization back-off for near-singular components, log-sum-exp E-step normalization, and closed-form M-step updates for all four covariance types
- **Synthetic-Data Validation** — convergence, monotonic log-likelihood increase, responsibilities summing to 1, parameter recovery (ARI = 0.988 vs. ground truth), and near-exact log-likelihood agreement with sklearn, all confirmed before fitting real faces
- **Hyperparameter and Component Selection** — a K sweep (5 to 50) evaluated on log-likelihood, held-out log-likelihood, BIC, AIC, silhouette, Davies-Bouldin, and Calinski-Harabasz, with an explicit discussion of why these criteria disagree
- **Covariance Structure Comparison** — `full` vs. `diag` vs. `spherical` vs. `tied` at fixed K=20, exposing a sharp `full`-covariance overfitting failure on held-out data
- **Initialization Sensitivity** — five single-restart (`n_init=1`) fits compared by log-likelihood spread and pairwise Adjusted Rand Index, motivating the multi-restart default used everywhere else
- **PCA Dimensionality Sensitivity** — refitting at 10 to 150 retained components to trade off fit time, held-out likelihood, and clustering quality
- **Covariance Regularization Sensitivity** — a `reg_covar` sweep from 1e-8 to 1e-2, identifying the stable range before regularization starts distorting the fit
- **Face Cluster Visualization** — component mean faces (reconstructed via inverse PCA) and each component's top-6 highest-responsibility members
- **Uncertainty and Responsibility Analysis** — the distribution of max-responsibility "confidence" and responsibility entropy across all 400 images, and a side-by-side view of the most ambiguous vs. most confident faces
- **sklearn Validation** — matched comparison against `sklearn.mixture.GaussianMixture` at K=20: log-likelihood/BIC/AIC agreement, plus a Hungarian-algorithm label alignment to compare hard assignments and mixture weights directly
- **Advanced Algorithm Comparison** — benchmarked against K-Means, Agglomerative Clustering, DBSCAN, and Bayesian GMM, evaluated with both internal (silhouette, Davies-Bouldin, Calinski-Harabasz) and external (ARI, NMI, homogeneity, completeness, V-measure, purity) metrics against the withheld subject labels
- **Stability and Sensitivity Summary** — a consolidated table of every sensitivity experiment run in the notebook

Key issues encountered and resolved during the project:

- **The last E-step value inside the fit loop is not the log-likelihood of the returned parameters** — the loop's E-step is evaluated *before* the corresponding M-step update, so the notebook explicitly recomputes the log-likelihood one more time from the final M-step parameters (`final_ll`) after the loop breaks, rather than reusing the last recorded value, to keep `lower_bound_` internally consistent
- **`full` covariance looked like the best model until the held-out set was checked** — at K=20 with ~16 training points per component, `full` covariance reaches the highest *training* log-likelihood but its *held-out* log-likelihood collapses to an extreme, deeply negative value (near-singular per-component covariance estimates assigning vanishing density to unseen faces); BIC's parameter-count penalty flags the same problem from the training set alone
- **Log-likelihood, BIC, AIC, and silhouette disagree on the "best" K, and the notebook reports the disagreement rather than picking one and hiding the rest** — BIC is minimized at the smallest K tested (K=5), AIC keeps improving toward the largest K tested, and silhouette favors the largest K tested (K=40); K=20 is kept for the remaining experiments as a stated, deliberate compromise, not the optimum by any single metric
- **Comparable objective values but low hard-assignment agreement with sklearn is not a bug** — the custom and sklearn implementations reach final log-likelihoods within about 0.9% of each other, but hard-assignment agreement after Hungarian label-alignment is only 18.8% (ARI 0.062); the initialization-sensitivity experiment already showed this is the expected signature of two independent EM runs landing in different (but similarly good) local optima at K=20, not evidence one implementation is wrong

K=20 with diagonal covariance is a deliberate compromise, not the optimum by any single model-selection metric: small enough to keep the `full`-covariance and PCA-dimensionality experiments computationally tractable, large enough for individual components to specialize into visually distinct, interpretable prototypes (BIC alone favors K=5, which merges most of the dataset's visual variety into just five broad prototypes).

## Limitations

- **EM converges to local optima**: five single-restart fits at K=20 produced final log-likelihoods spread over ~4% of their mean magnitude and a mean pairwise Adjusted Rand Index of only 0.101 between differently-seeded hard-assignment solutions; multi-restart fitting (`n_init >= 3`) is used everywhere a result is reported for exactly this reason.
- **`full` covariance overfits sharply at this sample size**: with ~16 training points per component at K=20, `full` covariance reaches the highest training log-likelihood but a catastrophically worse held-out log-likelihood than `diag`, `spherical`, or `tied`; `diag` is the standing default throughout.
- **The choice of K is a documented judgment call, not a uniquely correct answer**: BIC, AIC, and silhouette disagree on the best K across the {5, 10, 15, 20, 25, 30, 40, 50} sweep, and K=20 was selected as an explicit trade-off rather than an automatic rule.
- **High-dimensional covariance estimation is data-hungry**: full covariance is usable only at low K or with strong regularization, given only 400 images total.
- **Discovered clusters do not necessarily represent actual subject identities**: the custom GMM's ARI against subject identity (0.109) and NMI (0.621) are moderate, not high, confirming that visual similarity in PCA space (pose, lighting, coarse shape) is correlated with, but distinct from, identity.
- **PCA may discard identity-specific detail** that lies in low-variance directions; the PCA-dimensionality experiment explored this trade-off (10 to 150 components) but did not exhaustively search it.
- **Sample size is small (400 images, 10 per subject)**: every finding, especially the `full`-covariance overfitting and the Bayesian GMM's aggressive component-pruning, is partly a consequence of this and would need re-examination on a larger dataset before generalizing.

## What I learned:

1. **A Rank-Deficient, Data-Starved Covariance Is the First Thing High-Dimensional Face Data Breaks.**

With only 400 images and 40 components requested in the algorithm comparison (about 10 points per component), even a diagonal-covariance GMM is working with a thin margin, and a `full`-covariance model breaks outright: its training log-likelihood looks best of all four covariance structures, while its held-out log-likelihood collapses by several orders of magnitude. Watching that gap open up made the bias-variance trade-off in covariance estimation concrete in a way the closed-form M-step derivation alone doesn't.

2. **Comparable Objective Values With Low Assignment Agreement Is the Correct Signature of Two Independent EM Runs, Not a Bug.**

The custom implementation and sklearn's reach final log-likelihoods within about 0.9% of each other on identical data, strong evidence both are mathematically correct, yet hard cluster-assignment agreement after label alignment is only 18.8% (ARI 0.062). The initialization-sensitivity experiment (mean pairwise ARI of 0.101 across differently-seeded single-restart runs of the *same* implementation) predicted exactly this: EM is a non-convex local optimizer, and two independently-initialized runs landing in different, similarly-good local optima is expected, not a sign of a bug. Reporting the likelihood comparison and the assignment-agreement number together, rather than either alone, was necessary to interpret this correctly.

3. **Disagreeing Model-Selection Criteria Is a Finding, Not a Failure to Pick One.**

BIC (K=5), AIC (favors the largest K tested), and silhouette (K=40) each answer "what is a good K" differently on the same sweep, because each is measuring something different: complexity-penalized likelihood, a gentler complexity penalty, and pure clustering geometry respectively. Rather than silently picking whichever criterion produced the most flattering number, stating the disagreement and then making an explicit, justified trade-off (K=20, for interpretability and computational tractability in later experiments) was more honest and more useful than an automatic rule would have been.

4. **Multi-Restart Fitting Is Not Optional Polish at This Scale.**

Five single-restart fits at K=20 varied by 4% of their mean log-likelihood magnitude and agreed with each other (pairwise ARI ≈ 0.101) barely more than chance. A single random initialization is not trustworthy on its own for this dataset/K combination; every reported result in the notebook uses `n_init >= 3`, and the multi-restart baseline reliably beat every individual single-restart run.

5. **Soft Responsibilities Surface a Class of Observation Hard Clustering Cannot.**

99.7% of images had a max responsibility above 0.5, and the mean responsibility entropy (0.049) was tiny relative to its maximum possible value (2.996), meaning the model is usually confident. But the handful of high-entropy images sit meaningfully between two or more component prototypes, exactly the ambiguous cases a hard-clustering algorithm like K-Means would silently and confidently force into one bucket with no signal that the decision was a close call.

6. **Testing Alternative Algorithms Revealed a Genuine Trade-Off, Not a Ranking.**

K-Means and Agglomerative Clustering scored best against subject identity; DBSCAN was the only method that could flag points as noise; Bayesian GMM's automatic-relevance prior concluded the data supports far fewer effective components than the 40 requested; and the custom GMM uniquely provided calibrated per-observation uncertainty none of the hard-clustering methods can. There was no universal winner, only the best method for a stated objective, which is a more honest conclusion than picking the single-metric leaderboard topper.

7. **Numerical Stability Techniques Are Load-Bearing, Not Optional, at 60 Dimensions.**

Working in log-space throughout, Cholesky decomposition instead of explicit matrix inversion, log-determinants from the Cholesky diagonal, a regularization back-off for near-singular per-component covariances, and log-sum-exp normalization were all necessary; the notebook notes that without these, EM on a 60-dimensional feature space routinely produces `NaN` log-likelihoods within the first few iterations. The near-singular synthetic edge case (a 4-point blob with covariance 0.001·I) converging cleanly with no NaNs was the direct confirmation that the back-off logic works.
